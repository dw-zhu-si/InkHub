# 审稿—修订—复审闭环

每个问题都要经历证据确认、最小修订和原规则复审，不能以模型声称完成代替验证。

## 工作流

1. 对问题冻结来源版本、规则、证据章节、严重度、影响范围和建议 Agent/Skill。
2. 按问题类型选择最小必要能力，生成完整但不写回的章节修复稿，并保留修前文本。
3. 校验返回章节、来源版本、标题、卷边界和内容完整性；缺失、重复、越界或无实际变化时拒绝整批结果。
4. 默认只自动修订一次，随后用原规则和受影响的连续性规则重新审计。
5. 已解决、部分解决、新增问题和无法判断必须分别记录；未解决项保持可见。
6. 只有作者接受的修复稿才能进入事务化写回，写回后再次验证索引与正文哈希。

## 输出合同

- 问题与证据快照
- Agent/Skill 路由记录
- 修前/修后完整章节和理由
- 复审结果与剩余问题
- 可回滚写回记录

## 安全边界

- 原稿仍是权威来源；模型输出永远是提案，不是已完成修复。
- 不自动无限重试，不因失败重复产生计费调用。
- 每批结果必须持久化并可恢复，已计费的成功批次不能因后续失败丢失。
- 不覆盖来源版本已经变化的章节。
